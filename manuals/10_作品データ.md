# 作品を追加・修正する
[目次へ](00_ここから読む.md)

> 初めて操作する場合：[色を変えて戻す練習](15_最初の練習を一緒に進める.md)から始められます。英語は[用語辞書](16_英語と専門用語の辞書.md)、貼る範囲や実行結果は[コピーと確認](17_コピーと確認の手順.md)を参照してください。

今回は追加作品の取り込みも同期実行もしていません。この章は次に作業するときの手順です。

## 原本はAirtable
AniMoodのAnimeテーブルで作品を追加・修正します。GitHubの `data/anime.json` を手で増やしません。手修正は次の同期で置き換わります。

| 項目 | 入れる内容 |
|---|---|
| Title | 日本語の作品名 |
| English Title | 英語の作品名。公開候補に必要 |
| General Tags | 標準選択肢から作品の特徴。公開候補に必要 |
| Media Type / Episodes / Release Year / Airing Status | 形式・話数・年・放送状態。未確認なら推測で埋めない |
| Evaluation Status | 未評価／評価中／評価済み。本人の正式評価で管理 |
| Editor’s Take | 承認した公開用の見解。任意 |

すでにある作品でないか検索してから追加します。作品名やタグの確認は原本で行います。
新規作品は正式評価を受けるまで「未評価」です。既存10作品の正式承認は維持します。
英語名と一般タグがそろっても、本人評価済みになった意味ではありません。

## 公開対象と非公開情報
公開推薦への条件は英語名＋一般タグ。書き出し処理は不完全な行があると全体を止めて前のJSONを残すため、途中入力の行が原因で同期が失敗する場合があります。
Editor’s Take（管理人の見解）は「評価済み」＋Public Ready（公開可）＋本文がある場合のみ公開します。
参考メモ・個人の感想・評価根拠などの内部項目は公開しません。公開用欄に非公開メモを貼らないでください。

## 反映を確かめる
設定済みの同期は毎朝5:17日本時間を予定しています。実行に遅れが出る場合があります。
手動確認する場合はGitHubのActions（自動処理）で「Export AniMood data」（作品データ書き出し）を選び、Run workflow（実行）を押します。
成功後にJSON変更のコミットがあるか、Cloudflareの公開処理が成功したか、公開サイトの作品数と追加作品を確認します。
変更なしの実行ではデータ更新コミットは作られません。

## PCの作品数が古いとき
PCのJSONは自動同期しません。公開更新とPC更新は別です。
自分の未保存・未公開変更をバックアップしたうえで、GitHubの最新変更を比較して取り込みます。わからなければ「PCの編集を残して最新データだけ取り込みたい」と依頼してください。
現在のPCとGitHubの差を無視して全ファイルを上書きしません。

## 修正を戻す
Airtableで該当項目を元の内容へ戻して同期します。公開JSONだけを戻すと次の同期で再び変わるので、原本から直します。
