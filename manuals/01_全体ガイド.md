# 全体ガイド：まずは小さく1か所変える
[目次へ](00_ここから読む.md)

> 初めて操作する場合：[色を変えて戻す練習](15_最初の練習を一緒に進める.md)から始められます。英語は[用語辞書](16_英語と専門用語の辞書.md)、貼る範囲や実行結果は[コピーと確認](17_コピーと確認の手順.md)を参照してください。


## サイトは3種類のファイルでできている
| ファイル | たとえるなら | AniMoodでの役割 |
|---|---|---|
| index.html | 文章と部屋の配置図 | 見出し、入力欄、結果を置く場所 |
| assets/style.css | 内装 | 色、文字サイズ、余白、スマホ向け配置 |
| assets/app.js | 操作の係 | 言語切り替え、ボタン生成、結果表示 |
| assets/engine.js | 選考の係 | 条件に合わない作品を外し、順位を計算 |
| data/tag_scoring.json | 採点表 | どのタグがどの気分に何点合うか |
| data/anime.json | サイト向け作品一覧 | Airtableから生成される公開データ |

HTMLは `<p>文章</p>` のようにタグで囲みます。`p` は段落です。
CSSは `.sub { font-size: 20px; }` のように対象と見た目を書きます。
JavaScriptはクリック時などの処理を記述します。JSONは設定・データだけを書く形式で、コメントや末尾の余分なカンマは使えません。

## PC・GitHub・公開サイトは別々
1. PCで保存する：手元のファイルが変わる。
2. プレビューを見る：手元の変更をブラウザで試す。
3. GitHubへ保存する：変更を正式なコードとして記録する。
4. Cloudflareの公開処理が成功する：一般の人が見るサイトが変わる。

PCで保存しただけでは公開サイトは変わりません。GitHubの編集画面を変更してもPC側には自動で届きません。
Airtableの作品情報は別経路です。Airtable → 同期処理 → GitHubのJSON → Cloudflareという流れです。

## 最初の練習
[02](02_編集とプレビュー.md)でプレビューを起動し、[04](04_見た目.md)のアクセント色を1か所変えて保存します。
変化を確認したら元の色へ戻して保存してください。公開しなくても練習できます。

## 毎回の作業の順番
1. 今日やることを1つ決める。「ボタンの色を変える」など。
2. 編集するファイルのコピーを `.local` 内に残す。
3. 対応する個別マニュアルで目印を探す。
4. 1項目だけ変更して保存する。
5. プレビューで英語・日本語・狭い画面を確認する。
6. 問題なければ次の変更へ進む。公開は[12](12_確認と公開.md)に沿う。

## 編集の境界
`id` はJavaScriptが部品を見つける名前、`class` はCSSが見た目を指定する名前、`data-i` は翻訳の対応名です。
文字の内容だけ変えるときは、これらの名前をそのまま残します。
`.local/site` は自動生成される出力です。直接直しても次の生成で消えます。
`data/anime.json` も作品編集の原本ではありません。作品の修正はAirtableで行います。
