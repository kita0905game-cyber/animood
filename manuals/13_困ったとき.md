# 困ったとき・元に戻す
[目次へ](00_ここから読む.md)

> 初めて操作する場合：[色を変えて戻す練習](15_最初の練習を一緒に進める.md)から始められます。英語は[用語辞書](16_英語と専門用語の辞書.md)、貼る範囲や実行結果は[コピーと確認](17_コピーと確認の手順.md)を参照してください。


| 症状 | 最初に見る場所 |
|---|---|
| PCで変えたのに公開サイトが同じ | PCプレビューを見ているか。公開するまで本番は同じ |
| 日本語だけ変わらない | app.jsのjaとHTMLのdata-iのつづり |
| 英語だけ変わらない | HTMLの文章。結果カードならapp.jsのt(...) |
| 保存したら診断が動かない | JavaScriptのカンマ・引用符・括弧、削除したid |
| 新しい気分が出るが結果がない | moodNamesとJSONのmoodsの名前が一致するか |
| 新しいフィルターが効かない | filterNamesとhard_filtersの内部名、タグのつづり |
| スマホだけ見た目が違う | CSS末尾の700px以下用指定、日本語用指定 |
| プレビューが開かない | [02](02_編集とプレビュー.md)で再起動 |
| 新ページが404 | [11](11_別ページを追加.md)の許可リストとビルド |
| 作品数が増えない | Airtableの入力・同期結果・公開結果・PCデータを分けて確認 |
| 好みが以前のまま | このブラウザに保存されている。「保存した好みを消す」を使う |

## 直前の変更を戻す
エディターでCtrl＋Z → Ctrl＋S。複数ファイルを直した場合は各ファイルで戻します。
エディターを閉じて履歴が使えなければ、`.local` に取ったコピーを元のファイルへ戻します。
まず一番最後の変更だけを戻し、動く状態へ戻ったか確認します。

## 公開済みの変更を戻す
GitHubの履歴で、戻したい変更とその前の状態を確認します。PRをまとめて反映した変更なら、そのPRのRevert（変更を打ち消す）から戻すPRを作れる場合があります。
別の人の更新や作品同期まで巻き戻さないよう、対象の変更だけを戻します。確信がなければ「このコミットの画面変更だけ戻して」と依頼してください。
戻した後もCloudflareの公開成功と実サイトの確認が必要です。

## エラーを読むとき
構文チェックの `Unexpected token` は、予想外の記号があるという意味です。示された行の直前も見ます。JSONの末尾カンマ、JavaScriptの引用符の閉じ忘れがよくある原因です。
英語の文章に `'` を入れる場合、JavaScriptで外側も `'` だと途中で文字列が終わります。外側を `"` にするなど、対になる引用符をそろえます。

## 困ったら送る内容
「どの画面の何を変えたかったか」「編集したファイル」「最後に変えた部分」「今見えている症状」を伝えてください。エラー文があればそのまま添えてもらえると判断しやすくなります。
パスワードやAIRTABLE_PATの値は送らず、エラーの周囲に含まれていないか確認します。
