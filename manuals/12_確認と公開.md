# 変更を確認して公開する
[目次へ](00_ここから読む.md)

> 初めて操作する場合：[色を変えて戻す練習](15_最初の練習を一緒に進める.md)から始められます。英語は[用語辞書](16_英語と専門用語の辞書.md)、貼る範囲や実行結果は[コピーと確認](17_コピーと確認の手順.md)を参照してください。


## まず、どのファイルを変えたか確認
GitHubは他の作業や作品同期でも更新されます。PCの古いファイルで上書きしないよう、公開するファイルの現行版と比べます。
今回の手順書作成では公開操作はしていません。

## 公開前の確認
- 英語・日本語の両方で変更した箇所を確認。
- 気分・好み・好きな作品の3ルートで診断。
- 除外条件、該当なし、元作品が結果に出ないこと。
- スマホ幅で文字のはみ出し、リンク、押せるボタン。
- 新しいページはリンクから開いて戻れること。

### 「好きな作品から」の作品名検索
この欄は、すべての作品を長い一覧から探すためのものではありません。作品名を入力すると、入力した文字を英語タイトル・日本語タイトルの両方から探し、候補を最大12件に絞ります。

1. 「好きな作品から」を選ぶ。
2. 作品名の一部を入力する。英語でも日本語でもよい。
3. 表示された候補を1つ押す。
4. 「何が好きだった？」の理由を1つ以上選んで診断する。

候補を押したあと、欄が空になっても選択は残ります。選択中の作品名が1つだけ表示されます。違う作品に変えるときは、そのまま別の作品名を入力します。

JavaScriptや推薦設定を変えた場合、作業フォルダーのPowerShellで実行：

```powershell
node --check assets/app.js
node --check assets/engine.js
python -m json.tool data/tag_scoring.json > $null
node --test tests/v05.test.mjs
python tools/build_site.py
```
上から、JavaScriptの書き方、JSONの書き方、既存機能、公開用生成を確認します。
エラーが出たら公開せず[13](13_困ったとき.md)へ。テストが成功しても新しく足した項目は手で確認します。
単純な文章や色の変更なら、両言語・画面サイズの確認を中心にします。

## GitHubへ保存
対象：https://github.com/kita0905game-cyber/animood

1. 変更するファイルのあるフォルダーを開く。
2. Add file → Upload files（ファイル追加 → アップロード）で変更したファイルだけをアップロード。
3. `index.html` は一番上、`app.js` や `style.css` は `assets`、設定JSONは `data` へ置く。階層を間違えない。
4. 変更内容を確認し、Commit changes（変更を保存）へ内容の短い説明を書く。

秘密情報・`.local`・バックアップをアップロードしません。コード変更に作品JSONを混ぜません。
複数フォルダーをまたぐ変更は、mainへ少しずつ保存すると途中状態が公開されます。この場合は編集用ブランチ（変更をまとめる別の作業場所）を作り、変更を全部そろえてからPull request（変更の確認依頼）でまとめてmainへ反映します。
ブランチ名の例は `codex/add-adventure-mood`。GitHubのブランチ選択から作成し、各画面でそのブランチを選んでいることを確認します。迷ったら「この変更を一式で公開して」と依頼してください。

## 公開が終わったか確認
CloudflareのAniMoodプロジェクトで、今回のコミットのデプロイが成功したことを確認。
https://animood.pages.dev/ を開き、Ctrl＋F5で再読み込みし、実際に変えた箇所を見る。
「GitHubに保存できた」と「サイトに反映された」は別の確認です。

## ルールを変えるとき
推薦軸・点数・公開条件を変えるなら、対応する正式ルールも一緒に更新します。
作業開始時の `python tools/check_rules.py` はGitHub側のルール差分を確認する道具です。変更を読まずに `--accept-reviewed` を付けて通さないでください。
